## ADDED Requirements

### Requirement: Single workspace builds every platform
The repository SHALL be one Cargo workspace from which the desktop application for
macOS, Windows and Linux is built with the same source code and the command
`cargo build --release -p summrise`.

#### Scenario: Release build on any supported OS
- **WHEN** a developer with only `rustup` installed runs `cargo build --release -p summrise` on macOS, Windows or Linux
- **THEN** the pinned toolchain from `rust-toolchain.toml` is used and a `summrise` executable is produced without installing a system UI toolkit

### Requirement: Layered crate dependencies
The workspace SHALL keep the dependency direction `imaging ← dicom ← core ← ui ← apps/desktop`,
and only `ui` and `apps/desktop` SHALL depend on egui or eframe.

#### Scenario: Domain crates are UI-free
- **WHEN** `cargo tree -p summrise-core -e normal` is inspected
- **THEN** it contains neither `egui` nor `eframe`

### Requirement: Reproducible dependency resolution
`Cargo.lock` SHALL be committed and CI SHALL build with `--locked`.

#### Scenario: Lockfile drift is rejected
- **WHEN** a dependency change is pushed without an updated `Cargo.lock`
- **THEN** the CI build fails at `cargo build --locked`

### Requirement: Uniform quality gates
The workspace SHALL forbid `unsafe` code, treat clippy warnings as errors in CI, and be
formatted with the repository `rustfmt.toml`.

#### Scenario: Local CI command
- **WHEN** a developer runs `cargo xtask ci`
- **THEN** formatting check, clippy with `-D warnings` and the full test suite run and the command fails on the first violation

### Requirement: Real imaging data is never committed
The repository SHALL ignore DICOM files and DICOMDIRs by default and tests SHALL use
synthetic fixtures generated by `summrise-testkit`.

#### Scenario: Accidental add of patient data
- **WHEN** a developer runs `git add .` in a checkout containing `DICOMDIR` and `*.dcm` files
- **THEN** those files are not staged
